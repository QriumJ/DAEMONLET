# DAEMONLET Dots 개인 플러그인 연결 안내서

확인일 2026년 10월 1일 KST · 대상 `codex/belle-audio-lipsync-v1`의 Dots 연결 구현

이 안내서는 본인의 Mac에서 실행 중인 DAEMONLET 캐릭터에게 ChatGPT Work 또는 dot이 짧은 문장·포즈·상태를 전달하도록 설정하는 방법을 설명합니다. 먼저 개인 터널과 전용 키를 만들고, 앱에서 연결한 다음, 개인 플러그인을 통해 실제 표시와 음성을 확인합니다. 터널은 Mac에서 OpenAI로 나가는 HTTPS 연결을 사용합니다. 공개 수신 포트를 열 필요가 없습니다. [공식 Secure MCP Tunnel 안내](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

설정은 계정 소유자가 직접 진행합니다. 이 문서의 `<개인 터널 ID>`, `<개인 Platform 조직 ID>`, `<대상 ChatGPT 워크스페이스>`는 설명용 자리표시자입니다. 실제 ID나 키를 이 문서에 적어 배포하지 마세요.

## 1 시작 전에 준비할 것

- 현재 후보 기능이 포함된 Mac용 DAEMONLET 앱과 사용할 캐릭터 팩이 필요합니다. 기본 캐릭터는 지피쨩이며, 벨은 본인이 보유한 별도 `.petchar` 팩을 가져와 선택해야 합니다.
- 이번 로컬 Mac 후보는 **Apple Silicon arm64, macOS 13 이상**을 빌드 대상으로 합니다. 앱 메타데이터와 Keychain·받아쓰기·Option 상태 도우미도 macOS 13을 대상으로 맞췄습니다. 실제 GUI 검증은 macOS 27에서만 수행했으므로 macOS 13의 실기기 호환성을 보증하지 않습니다. Intel·다른 macOS 버전은 이번 후보의 검증 대상이 아닙니다.
- **음성을 사용할 때** Apple Silicon Metal용 음성 엔진·모델과 사용 가능한 음성 설정이 별도로 필요합니다. 기본 음성 런타임의 빌드 하한은 macOS 13이며 Intel Mac은 이 음성 경로를 지원하지 않습니다. 실제 검증 기록은 Apple Silicon/macOS 27 환경에 한정됩니다. 모델 준비가 안 된 상태에서도 먼저 문장 표시만 시험할 수 있습니다.
- 외부 **Node.js 22.13 이상**, 공식 **tunnel-client 0.0.14 이상 및 앱이 요구하는 기능**이 필요합니다. Dots 연결 화면은 이 구성 요소를 자동 설치하지 않습니다.
- 본인 OpenAI 계정의 개인 Platform 조직, 사용할 ChatGPT 워크스페이스, 해당 워크스페이스의 개발자 모드 접근이 필요합니다. 조직의 터널 권한과 ChatGPT 개발자 모드 권한은 별개입니다.
- 시험하는 동안 Mac이 깨어 있고 인터넷에 연결되어 있으며 DAEMONLET이 실행 중이어야 합니다. 앱 종료 시 앱이 시작한 연결은 종료됩니다.

기본 앱을 실행해 캐릭터를 표시하는 데 음성용 Python·모델·ComfyUI·NVIDIA GPU가 모두 필요한 것은 아닙니다. 음성은 별도 기능입니다. 벨 전용 학습 음성을 쓰려면 기존의 검증된 음성 패키지와 지원 런타임을 준비해야 하며, 터널 연결만으로 새 음성이나 모델이 설치되지 않습니다. [앱 설치 근거](install-macos.md), [기본 음성 설치 근거](character-chat-voice-base-install.md), [Mac 음성 근거](character-chat-voice-macos.md)

**후보 상태를 확인하세요.** 이 안내서는 새 후보의 Developer ID 서명·Apple 공증 완료를 인증하지 않습니다. 이전 공개 릴리스의 서명·공증은 새 바이너리에 승계되지 않습니다. Windows/Linux의 Dots 연결은 현재 안전한 키 저장소를 지원하지 않아 키 저장·연결을 차단합니다. 새 Belle **1.2.3 후보 팩**은 기존 **37개 포즈**에 입만 움직이는 립싱크를 적용합니다. 턱·얼굴·원본 그림은 오디오로 변형하지 않습니다. 해당 팩의 새 capability를 지원하는 **동반 후보 앱**이 필요하며, 이전 한 포즈 파일럿 앱과 섞어 설치하지 마세요. 기존 설치 팩은 자동 교체되지 않습니다. 37포즈의 닫힘·작게·크게와 대표 8포즈의 실제 벨 파형 재생을 격리 무음 출력에서 확인했지만, 새 리비전의 개인 플러그인 실제 표시·청취는 소유자 검수 항목입니다. Windows 후보와 실시간 음소 인식은 완료된 기능으로 안내하지 않습니다. [현재 립싱크 범위](belle-audio-lipsync-all-poses.md)

## 2 조직과 워크스페이스와 Mac 구분하기

세 이름은 서로 다른 대상을 가리킵니다. 같은 계정으로 로그인해도 ID와 역할이 같아지지는 않습니다.

| 대상 | 쉽게 이해하기 | 이 연결에서 하는 일 |
| --- | --- | --- |
| 개인 Platform 조직 | OpenAI 개발자 설정을 관리하는 계정의 공간 | 개인 터널과 런타임 키를 만들고 터널 권한을 관리합니다. 앱의 **Platform 조직 ID**에는 이 조직의 `org-…` 값을 넣습니다. |
| ChatGPT 워크스페이스 | ChatGPT에서 대화와 플러그인을 사용하는 공간 | 개인 플러그인을 만들고 설치할 곳입니다. 터널이 이 워크스페이스에도 연결되어 있어야 합니다. |
| 본인의 Mac | DAEMONLET과 터널 클라이언트가 실제로 실행되는 기기 | 문장을 화면에 표시하고 기존 음성 엔진으로 읽습니다. Mac이 꺼지면 이 출력 경로도 사용할 수 없습니다. |

회사나 학교의 Platform 조직을 임의로 개인 조직 대신 선택하지 마세요. 개인 조직에만 연결한 터널이 회사·학교 ChatGPT 워크스페이스에 자동으로 보이는 것도 아닙니다. 사용할 워크스페이스와 터널의 연결 대상을 맞추세요. [공식 조직과 워크스페이스 연결 설명](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels#associate-tunnels-with-the-right-organizations-and-workspaces)

dot의 **컴퓨터 접근 허용**과 이 개인 MCP 플러그인 연결도 별개입니다. 이번 출력 도구는 파일 읽기·명령 실행·대화 내역 제공을 지원하지 않습니다. 출력 연결을 위해 전체 컴퓨터 접근을 반드시 허용한다고 안내하지 않습니다. dot이 설치·활성화된 지원 플러그인을 사용할 수 있는지는 계정 권한과 실행 환경에 따라 달라집니다. [공식 dot 컴퓨터와 앱 안내](https://learn.chatgpt.com/docs/dots/computers-and-apps)

## 3 공식 클라이언트 설치와 버전 확인

Homebrew가 준비되어 있다면 터미널에서 다음 명령을 실행합니다. 키나 개인 ID는 들어 있지 않습니다.

```sh
brew install openai/tools/tunnel-client
tunnel-client --version
tunnel-client help quickstart
node --version
```

이미 설치한 공식 클라이언트가 오래된 경우에는 다음 명령으로 업데이트한 뒤 버전을 다시 확인합니다.

```sh
brew upgrade openai/tools/tunnel-client
tunnel-client --version
```

현재 앱의 최소 클라이언트 검사는 0.0.14 이상입니다. 숫자만 충족해도 충분한 것은 아니며, 앱은 필요한 health·stdio 옵션도 확인합니다. 위 명령이 성공한 뒤 DAEMONLET을 다시 열고 **Dots 연결 → 상태 다시 확인**을 누르세요. [공식 Homebrew 설치 안내](https://github.com/openai/tunnel-client#install-with-homebrew)

공식 안내는 macOS에서 Homebrew 설치를 지원합니다. 수동 다운로드 ZIP이 Gatekeeper에 막히면 `xattr`·`spctl` 또는 보안 예외로 우회하지 말고 공식 설치 경로를 사용하세요. Homebrew가 없다면 먼저 [Homebrew 공식 설치 안내](https://brew.sh/)를 확인합니다. 확인일 기준 Homebrew의 공식 Mac 지원은 macOS Sequoia 15 이상입니다. 이 설치 도구의 지원 기준도 음성 엔진의 빌드 하한과 구분하세요. Node.js가 없거나 22.13보다 낮으면 [Node.js 공식 다운로드 안내](https://nodejs.org/en/download)를 확인하세요. 기존 개발 환경을 바꾸기 전에는 그 환경을 사용하는 작업도 확인합니다.

터미널에서만 활성화되는 Node 버전 관리 환경은 앱이 찾지 못할 수 있습니다. 현재 앱은 Homebrew와 표준 로컬 설치 위치를 탐색합니다. **NODE_MISSING**이 나오면 터미널의 버전 표시와 앱에서 확인한 Node 버전을 구분하세요. 키를 명령줄에 붙이거나 터널 데몬을 별도로 실행할 필요는 없습니다. 이 안내서에서는 앱이 연결을 관리합니다.

## 4 본인의 개인 터널과 전용 키 만들기

### 개인 터널 생성

1. 본인 계정으로 [Platform 터널 설정](https://platform.openai.com/settings/organization/tunnels)을 엽니다.
2. 현재 선택된 조직이 **본인의 개인 Platform 조직**인지 확인합니다. 터널 생성에는 Tunnels **Read + Manage** 권한이 필요합니다.
3. 터널 만들기 항목에서 알아보기 쉬운 이름을 정합니다. 예를 들어 `내 Mac DAEMONLET`처럼 기기의 용도를 적습니다.
4. 연결 대상에 개인 Platform 조직과 `<대상 ChatGPT 워크스페이스>`가 포함되어 있는지 확인합니다. 화면에 선택할 대상이 없거나 연결을 확인할 수 없으면, 다른 조직으로 임의 변경하지 말고 해당 계정의 관리자나 공식 지원 경로에서 확인합니다.
5. 생성된 `<개인 터널 ID>`와 `<개인 Platform 조직 ID>`를 본인이 확인합니다. 터널 ID는 `tunnel_…`, Platform 조직 ID는 `org-…` 형태입니다. 뒤에서 앱과 플러그인에 같은 터널 ID를 사용합니다.

화면의 버튼 이름은 계정과 시점에 따라 달라질 수 있습니다. 위 순서는 공식 터널 생성·연결 절차를 설명하며 모든 계정에서 동일한 화면이 나타난다는 보증은 아닙니다. [공식 터널 생성 안내](https://github.com/openai/tunnel-client/blob/master/docs/end-user-guide.md#create-the-tunnel)

### Restricted 런타임 키 생성

1. 같은 개인 조직의 [Platform 런타임 API 키](https://platform.openai.com/settings/organization/api-keys)를 엽니다.
2. 이번 연결에만 쓸 새 키를 본인이 만듭니다. 권한은 **Restricted**, Tunnels는 **Read + Use**로 설정하고 필요한 범위를 확인합니다. **All 권한 키나 Admin key를 앱에 넣지 마세요.**
3. 키를 만든 사용자 또는 서비스 계정에도 대상 터널의 **Read + Use** 권한이 있어야 합니다. 제한 키를 만드는 것만으로 사용자에게 없던 조직 권한이 생기지는 않습니다.
4. 새 키를 본인이 확인하고 다음 절의 DAEMONLET 비밀번호 입력란에 직접 입력합니다. 키를 채팅·이메일·스크린샷·공유 문서·터미널 명령에 보내지 마세요. 다른 사람이나 에이전트에게 키를 읽거나 대신 입력하게 요청하지 않습니다.

터널을 만드는 권한인 **Manage**와 연결을 실행하는 권한인 **Use**는 다릅니다. 전용 런타임 키는 터널 실행용이며, 터널 생성용 Admin key와 분리합니다. 앱은 입력된 키의 실제 원격 권한을 검사할 수 없으므로 권한 설정은 소유자가 Platform에서 확인해야 합니다. [공식 터널 권한과 제한 키 안내](https://github.com/openai/tunnel-client/blob/master/docs/permissions.md#creating-keys)

**Restricted 키는 무료 사용 보증이 아닙니다.** 이 문서는 터널·ChatGPT 플랜·API 이용의 요금이나 한도를 보장하지 않습니다. 별도 API 모델 호출이나 다른 유료 서비스를 사용한다면 해당 계정의 현재 요금·결제·사용 제한을 확인하세요.

## 5 앱에서 키를 저장하고 연결하기

기존에 터미널 도우미로 같은 터널을 실행했다면 먼저 그 터미널에서 직접 종료하고, 그 방식으로 실행한 앱도 종료합니다. 이후 DAEMONLET을 일반 실행하세요. 기존 `DAEMONLET_DOT_BRIDGE`나 키 환경변수를 상속한 외부 세션을 새 앱 설정이 자동으로 인수하거나 종료하지 않습니다. 같은 터널의 stdio 클라이언트는 하나만 활성 상태여야 합니다. [공식 중복 실행 제한](https://github.com/openai/tunnel-client#install-with-homebrew)

1. DAEMONLET에서 사용할 벨 팩을 선택하고 캐릭터가 화면에 표시되는지 확인합니다. 로컬 캐릭터 대화·Codex 작업 대화·실험 화면이 캐릭터를 사용 중이면 시험 전에 닫습니다.
2. 앱 메뉴의 **설정 → Dots 연결**을 엽니다. 한국어 화면의 탭 이름은 **Dots 연결**, 영어는 **Dots connection**입니다.
3. **터널 ID**에 `<개인 터널 ID>`, **Platform 조직 ID**에 `<개인 Platform 조직 ID>`를 입력합니다. ChatGPT 워크스페이스 ID를 조직 ID 입력란에 넣지 마세요.
4. **전용 키**에 본인이 만든 Restricted 런타임 키를 직접 입력하고 **키 저장·대상 확인**을 누릅니다.
5. 앱의 기본 macOS 확인 창에서 대상 터널·조직·허용 기능과 키 보관 기간을 읽습니다. 본인의 대상이 맞으면 **허용**을 선택합니다. 기본 선택은 **취소**입니다. 키는 삭제할 때까지 이 앱의 Keychain 항목에 보관되며 다시 표시되지 않습니다.
6. 저장 후 **연결**을 누릅니다. 이번에도 별도의 확인 창에서 대상을 확인하고 허용합니다. **저장만으로 연결되지는 않습니다.**
7. **터널 준비됨** 표시를 확인한 뒤 다음 절의 플러그인을 만듭니다. 이 표시는 통로의 준비 상태이며 실제 도구 발견·문장 표시·음성 재생까지 확인했다는 뜻은 아닙니다.

키는 macOS Keychain에 보관되며 JSON 설정·로그·앱 파일에 평문 키를 저장하는 방식으로 대체하지 않습니다. Keychain이 잠겼거나 접근을 거부하면 연결이 실패합니다. macOS가 추가 Keychain 접근 확인을 표시할 수 있으며, 정확한 문구와 표시 시점은 시스템 및 앱 서명 상태에 따라 달라질 수 있습니다. 이 안내서가 실제 서명 후보에서 그 권한 창을 검증했다는 뜻은 아닙니다.

처음에는 **앱 시작 시 자동 연결**을 꺼 둡니다. 실제 출력 시험을 마친 후 원할 때만 켜고 별도의 지속 접근 확인을 허용하세요. 이 옵션은 앱을 직접 열 때마다 저장된 키로 연결합니다. OS 로그인 서비스를 만들지 않으며, 재연결할 때도 음성은 기본 음소거 상태로 시작합니다.

앱 배포본은 도우미를 자동으로 찾습니다. Keychain 도우미는 `.app/Contents/Resources/native/DaemonletBelleCredential`, MCP 어댑터와 수명 관리 도우미는 `.app/Contents/Resources/dot/dot-presentation-mcp.mjs`와 `belle-tunnel-supervisor.mjs`에 들어 있습니다. 개발 실행에서는 같은 파일이 저장소의 `dist-electron/native/`와 `dist-electron/dot/`에 있습니다. 기존 개발용 터미널 명령을 배포 앱의 실행 방법으로 복사하지 말고 일반 앱의 **Dots 연결** 화면을 사용하세요. 배포본에도 Node.js와 공식 tunnel-client는 포함되지 않으므로 앞 절의 외부 설치·버전 확인이 필요합니다.

## 6 Tunnel 방식으로 개인 MCP 플러그인 연결하기

MCP는 플러그인이 `present`와 `cancel` 같은 도구를 호출하는 연결 규칙입니다. 이 앱의 개인 출력 도구는 문장·포즈·상태 표시와 취소만 제공합니다.

1. DAEMONLET의 연결을 켜 둡니다. ChatGPT에서 앞서 터널과 연결한 `<대상 ChatGPT 워크스페이스>`를 선택합니다.
2. 사용 가능한 계정에서 **Settings → Security and login → Developer mode**를 켭니다. 회사·학교 워크스페이스에서 권한이 없다면 해당 관리자에게 접근을 요청해야 합니다.
3. [ChatGPT Plugins](https://chatgpt.com/plugins)에서 추가 버튼으로 개인 개발자 플러그인 연결을 시작합니다. **Connection → Tunnel**을 선택하고 본인의 터널을 고르거나 `<개인 터널 ID>`를 입력합니다.
4. 연결 정보를 확인하고 알아보기 쉬운 개인 플러그인 이름을 지정합니다. 새 연결의 이름은 예를 들어 `DAEMONLET Dots`로 구분할 수 있습니다. 이미 만든 플러그인이나 터널의 이름은 그대로 사용하며, Dots 명칭을 맞추기 위해 바꿀 필요가 없습니다.
5. 발견된 도구가 **present**, **cancel**인지 확인합니다. 다른 도구나 임의 파일·명령 접근이 보이면 여기서 설명하는 앱 출력 도구인지 다시 확인합니다.
6. [개인 Plugins 목록](https://chatgpt.com/plugins/personal)에서 만든 플러그인을 설치합니다. 새 **Work** 대화의 입력란에서 `@`로 해당 플러그인을 선택하고 다음 절의 시험을 요청합니다.

개인 플러그인 생성·설치·Work에서 호출하는 순서는 [공식 플러그인 Quickstart](https://developers.openai.com/plugins/quickstart)를, Tunnel 선택은 [공식 터널 연결 안내](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels#connect-from-chatgpt)를 따릅니다. 계정 정책과 제품 버전에 따라 연결 화면이나 사용 가능한 항목이 다를 수 있습니다.

앱 내부의 `/present` HTTP 주소는 MCP 서버 주소가 아닙니다. localhost 주소를 플러그인 URL로 붙이거나 인터넷에 공개하지 마세요. 이번 개인 Tunnel 경로는 공개 플러그인 배포 경로와 구분됩니다. 안내서를 공유해도 다른 사용자는 본인 계정의 터널·키·플러그인을 직접 만들어야 합니다.

## 7 첫 문장과 음성 시험

### 먼저 화면 표시 확인

Work 입력란에서 `@`로 본인의 플러그인을 선택한 뒤 아래처럼 요청합니다.

```text
present 도구를 한 번 호출해 줘.
text는 "안녕하세요. Dots 연결을 확인하고 있어요.",
pose는 "happy", state는 "done", speak는 false,
durationMs는 12000으로 해 줘.
```

Mac에서 같은 문장이 표시되는지 직접 확인합니다. `accepted:true`는 앱이 요청을 받아들였다는 응답입니다. 선택한 캐릭터 팩이 표시되는지, 말풍선이 보이는지까지 확인해야 첫 표시 시험이 끝납니다. 팩에 해당 포즈 규칙이 없으면 기본 포즈로 돌아갈 수 있습니다.

### 음소거 상태와 기존 음성 확인

연결 시 음성은 기본 음소거입니다. 위 요청을 `speak:true`로 바꿔 한 번 호출하면 음소거 상태에서는 `voice:muted`가 반환되고 문장만 표시될 수 있습니다. 아직 원격 도구에서 음소거를 풀 수는 없습니다.

1. **설정 → 대화·음성 → 캐릭터 음성**에서 기존 음성 사용이 켜져 있고, 현재 캐릭터의 음성 패키지·런타임·모델·재생 준비 상태가 정상인지 확인합니다. 음량도 0보다 높게 둡니다.
2. 음성 준비 때문에 로컬 대화를 열었다면 시험 전에 다시 닫습니다. 캐릭터 화면을 다른 대화가 사용 중이면 dot 출력이 거절됩니다.
3. Mac의 앱 트레이 메뉴에서 **dot 표현 · 현재 세션** 아래 **음소거** 체크를 직접 해제합니다. **표현 일시 중지**도 꺼져 있는지 확인합니다.
4. 아래처럼 짧은 발화를 요청하고 Mac의 스피커 또는 선택한 출력 장치에서 실제로 들리는지 확인합니다.

```text
present 도구를 한 번 호출해 줘.
text는 "안녕하세요. 지금은 음성 연결을 확인하고 있어요.",
pose는 "neutral", state는 "speaking", speak는 true,
durationMs는 30000으로 해 줘.
```

`voice:requested`는 음성을 요청했다는 뜻이며 재생 완료나 실제 들림을 보증하지 않습니다. 첫 준비에는 시간이 걸릴 수 있습니다. 소리가 나지 않으면 반복 호출을 쌓지 말고 아래 문제 해결 순서를 확인합니다. 재생 중 `cancel` 도구를 빈 인수 `{}`로 호출하거나 Mac의 **현재 표현 중단**을 눌러 멈출 수 있는지도 확인합니다.

### 기존 음성 정책은 그대로 사용

Dots 연결은 기존에 선택한 캐릭터·음성 패키지·음량·시드 정책을 사용합니다. 모델이나 화자를 바꾸지 않습니다. **새 음성의 시드**는 기본적으로 **답변마다 무작위**이며 **고정**을 선택할 수도 있습니다. 시드는 다음 합성에 적용되고, 같은 시드라도 다른 기기·엔진·버전에서 동일한 녹음을 보장하지 않습니다. 기존 Metal **청크 재생** 또는 **완성 후 재생** 설정도 유지합니다. 청크 재생은 생성된 음성 조각을 순서대로 재생하는 기능이며 전화식 양방향 실시간 대화와는 다릅니다. [시드 정책](character-chat-voice-seeds.md), [재생 방식](character-chat-voice-base-install.md)

입 움직임은 동반 후보 앱에서 Belle 1.2.3의 선택된 포즈에 실제 오디오가 재생될 때 작동합니다. MCP `pose`는 semantic enum이며 팩 내부의 `waiting-open` 같은 ID를 직접 입력하지 않습니다. 일반 `neutral` 한 번의 시험이 37포즈 전부를 검사하는 것은 아닙니다. 발화 중 무음·음소거에는 입을 닫고, 출력 소유권이 끝나면 원래 표정을 복원합니다. 마지막 heartbeat가 유실된 경우 direct/dot lease는 약 250ms, 로컬 대화의 watchdog+lease는 약 500ms 뒤 복원될 수 있습니다(이벤트 루프 지연 제외).

### 후보 앱·팩을 함께 적용하고 되돌리기

1. 현재 사용하는 앱과 기존 Belle `.petchar`를 보관합니다. 앱 종료와 후보 실행은 소유자가 직접 진행합니다.
2. 동반 후보 앱에서 **캐릭터·표시 → 캐릭터 추가**로 새 Belle 1.2.3을 가져옵니다. 같은 `belle` ID의 새 리비전이 현재 선택이 됩니다. 원본 그림·페르소나·음성 자산은 보존되며, 이전 리비전도 저장소에 남습니다.
3. 되돌리려면 **캐릭터·표시 → 이전 버전 복원**에서 확인 창을 읽고 이전 리비전을 선택합니다. 이전 앱으로 돌아갈 때에는 이전 앱이 지원하는 1.2.2 등 이전 팩으로 먼저 복원합니다.
4. 같은 개인 프로필의 설정·키를 작업자가 이동하거나 덮어쓰지 않습니다. 새 로컬 서명 앱의 Keychain 접근에는 별도 macOS 확인이 나타날 수 있으므로 소유자가 직접 판단합니다. 키 재입력 불필요를 새 바이너리에 대해 보장하지 않습니다. 모델·음성 런타임 경로도 실제 후보에서 검사하고, 호환성 오류를 무시하지 마세요.

새 앱의 **캐릭터·표시**에서는 크기를 20~400%, 불투명도를 0~100%로 직접 설정할 수 있습니다. 50% 이하에서는 캐릭터 뒤로 클릭이 통과합니다. **트레이 → 불투명도 100% 복원** 또는 설정의 복원 버튼을 사용하면 0%에서도 돌아올 수 있습니다. Mac의 Option+휠 보조 경로와 물리 조작 검수 범위는 [크기·불투명도 안내](character-size-opacity.md)를 확인하세요. 말풍선·작업창의 불투명도와 음성·개인 연결 설정은 이 조절에 포함되지 않습니다.

## 8 대화 중 문맥에 맞게 출력 요청하기

dot이나 Work에 다음 지시를 전달할 수 있습니다. 플러그인이 설치·활성화되어 있어야 하며, 해당 환경에서 도구를 선택하는지는 별도로 확인해야 합니다.

```text
내가 연결한 DAEMONLET 캐릭터 플러그인을 사용할 수 있고 Mac 앱이 준비되어 있을 때,
이 대화의 완료된 답변 중 현재 선택한 캐릭터에게 보여 주면 도움이 되는 짧은 요약을
present로 한 번 전달해 줘. text는 600자 이내의 완결된 한국어 문장으로 쓰고,
문맥에 맞는 pose와 state를 선택해 줘.

처음에는 speak:false로 보내 줘. 내가 이 대화에서 음성 출력을 요청한 뒤에는
필요한 짧은 완료 문장에 speak:true를 사용할 수 있어.
음소거와 일시 중지는 Mac의 내 선택을 따라 줘.

대화 전체나 긴 답변을 자동으로 읽지 말고, 적절한 출력이 없으면 호출하지 마.
도구를 사용할 수 없거나 거절되면 원래 대화는 계속하고,
이전 출력을 나중에 몰아서 다시 보내지 마.
내가 벨 출력을 멈추라고 하면 cancel을 호출해 줘.
```

이 지시는 출력 선택을 돕는 요청입니다. 모든 답변을 자동 구독하거나 모든 메시지의 상태를 수신하는 기능을 추가하지 않습니다. 답변마다 호출되는 보증도 없습니다. 꼭 확인할 출력은 `@플러그인`과 함께 명시적으로 `present`를 요청하세요.

도구의 `pose`는 `neutral`, `listening`, `thinking`, `happy`, `sad`, `error`, `state`는 `idle`, `thinking`, `speaking`, `done`, `error`를 사용할 수 있습니다. 화면의 실제 그림은 팩의 포즈 규칙을 따릅니다. `text`는 최대 600 Unicode 문자, 표시 시간은 1~30초이며 기본 12초입니다. 새 출력이 이전 출력을 대체하고 시간이 끝나면 해제됩니다. 음성도 취소될 수 있으므로 긴 답변은 짧게 요약해 요청합니다. 로컬·작업 대화의 기록에 원격 출력 문장이 자동 추가되지는 않습니다.

같은 dot을 휴대전화에서 부르더라도 이 연결의 출력 장소는 켜져 있는 Mac입니다. dot의 연락 채널과 플러그인·컴퓨터 접근은 별도입니다. 휴대전화의 마이크·스피커로 이어지는 네이티브 양방향 음성 통화, Mac이 꺼져 있을 때의 출력, 휴대전화에서의 자동 도구 호출은 이 안내서에서 보장하지 않습니다. [공식 dot 접근 범위](https://learn.chatgpt.com/docs/dots/computers-and-apps)

## 9 연결 문제 해결하기

문제가 생기면 **통로 준비 → 플러그인 도구 발견 → 실제 문장 표시 → 실제 음성** 순서로 나누어 확인합니다. 지원 요청에는 공개 오류 코드와 수행한 시험만 전달하고 키·개인 ID·개인 경로는 가립니다.

### 터널 준비됨인데 플러그인이 작동하지 않음

앱의 `터널 준비됨`은 클라이언트 준비 검사 결과입니다. stdio 도구 발견이 끝났다는 증거는 아닙니다. 같은 터널 ID를 플러그인에 선택했는지, 대상 ChatGPT 워크스페이스 연결과 Read + Use 권한이 맞는지 확인한 다음 `present`를 한 번 명시적으로 요청합니다. [공식 준비 상태와 발견 상태 구분](https://github.com/openai/tunnel-client/blob/master/docs/end-user-guide.md#get-to-first-success-in-the-terminal)

터널 목록에 보이지 않으면 새 터널을 계속 만들기 전에 조직·워크스페이스 연결과 생성자의 Use 권한을 확인하세요. 새로운 권한 부여는 반영에 시간이 걸릴 수 있습니다. 앱의 재연결은 제한되어 있으므로 계속 실패할 때는 **연결 해제·자동 연결 끄기** 후 원인을 고치고 다시 연결합니다.

### 오래된 클라이언트나 중복 세션

`CLIENT_MISSING`, `CLIENT_VERSION`은 공식 설치와 버전·필요 기능을 확인합니다. `NODE_MISSING`, `NODE_VERSION`은 앱이 탐색할 수 있는 Node.js 22.13 이상인지 확인합니다. `ADAPTER_MISSING`은 배포 앱의 연결 구성 요소가 빠졌을 수 있으므로 해당 후보 패키지를 확인합니다.

**외부 터미널 세션 사용 중**이면 기존 도우미를 실행한 터미널에서 직접 종료합니다. 앱 설정의 연결 해제로 외부 도우미까지 종료되지는 않습니다. 같은 터널 ID로 두 클라이언트를 동시에 실행하지 마세요. 임의 프로세스를 일괄 종료하는 명령을 복구 방법으로 사용하지 않습니다.

### 키나 연결 대상 오류

`INVALID_CONFIG`는 터널 ID와 Platform 조직 ID의 종류·오탈자를 확인합니다. `INVALID_KEY` 또는 `KEY_MISSING`은 본인이 전용 키를 직접 다시 입력합니다. `STORE_LOCKED`, `STORE_DENIED`, `STORE_UNAVAILABLE`은 Keychain 잠금·거부 또는 앱 보안 구성 요소 문제를 확인한 뒤 **상태 다시 확인**을 누릅니다. 파일에 키를 저장하는 우회는 하지 않습니다.

`CONNECTION_FAILED`는 네트워크, 대상 터널, 개인 조직, 런타임 키의 Read + Use 권한과 중복 클라이언트를 확인합니다. 키를 생성한 주체의 권한도 확인하세요. 앱은 키 권한의 세부 내용을 보여 주지 않습니다.

### DOT_UNAVAILABLE 또는 문장이 보이지 않음

캐릭터를 표시하고 로딩·크기 조절을 마칩니다. 로컬 캐릭터 대화, Codex 작업 대화, 실험 화면이 캐릭터를 사용 중이면 닫고 다시 시험합니다. 캐릭터를 바꾸거나 앱이 종료 중인 경우에도 출력이 거절될 수 있습니다. **LOCAL_NOT_READY**도 캐릭터 화면 준비 상태를 확인합니다. 사용할 수 없을 때 받은 출력은 나중에 자동 재생되지 않습니다.

`DOT_QUIET`이면 Mac 메뉴의 **표현 일시 중지**를 확인합니다. 말풍선 설정도 존중되므로 표시 기능이 꺼져 있지 않은지 확인합니다. `poseFallback:true`는 팩의 지원 포즈를 확인하는 단서이며 반드시 연결 실패를 뜻하지는 않습니다.

### 글이 길거나 말풍선이 금방 닫힘

긴 문장은 짧은 미리보기와 **전체 보기**로 표시될 수 있습니다. 펼친 본문은 화면 안에서 스크롤하며 Escape로 접을 수 있습니다. 전체 보기를 눌러도 표시 만료 시간은 늘어나지 않습니다. 읽는 도중 닫히면 허용 범위 안에서 `durationMs`를 늘리거나 더 짧은 요약을 요청합니다. 600자를 넘는 원문은 짧게 나누어 요청하되 새 호출이 기존 표시·음성을 대체한다는 점을 고려합니다.

### 소리가 나지 않거나 도중에 멈춤

`voice:muted`면 Mac의 **음소거**를 직접 해제합니다. `DOT_VOICE_UNAVAILABLE`이면 기존 음성 사용·선택 패키지·지원 런타임·모델·재생 준비 상태를 확인합니다. `voice:requested`만으로는 실제 소리를 확인할 수 없습니다. 앱 음량과 macOS 출력 장치를 확인하고 짧은 문장을 한 번 시험하세요. 새 출력, `cancel`, 만료, 캐릭터 숨김·변경 등은 기존 음성을 중단할 수 있습니다. 첫 출력이 조용하거나 불안정하면 해당 후보의 오디오 검증 항목으로 기록하며 모든 후속 호출이 정상이라고 단정하지 않습니다.

## 10 사용을 멈추고 접근 정리하기

현재 문장·음성만 멈추려면 **현재 표현 중단** 또는 `cancel({})`을 사용합니다. **음소거**는 소리를 차단하고 현재 출력을 취소할 수 있으며, **표현 일시 중지**는 새 표현을 거절합니다. 이 조작만으로 원격 터널 권한이 취소되지는 않습니다.

연결까지 멈추려면 **설정 → Dots 연결 → 연결 해제·자동 연결 끄기**를 누릅니다. 앱이 시작한 연결을 종료하고 앱 시작 시 자동 연결도 끕니다. 앱 종료 역시 앱이 소유한 연결을 종료하지만, 저장 키와 자동 연결 선택 자체를 삭제하지는 않습니다. 외부 터미널 도우미는 그 실행 위치에서 별도로 종료하세요.

더 이상 사용하지 않을 때는 본인이 다음 항목을 각각 정리합니다.

1. 앱에서 **저장한 키·설정 삭제**를 누르고 대상 확인 창을 읽은 뒤 허용합니다. 이 앱의 Keychain 항목과 연결 설정이 삭제됩니다.
2. Platform에서 이번 연결용 런타임 키를 **폐기**합니다. 로컬 Keychain 삭제나 앱 삭제만으로 원격 키가 폐기되지 않습니다.
3. ChatGPT 개인 Plugins에서 해당 플러그인의 설치·연결을 해제하고 더 이상 필요 없는 개인 플러그인을 삭제합니다. 실제 화면의 제공 작업과 계정 권한을 확인합니다.
4. Platform에서 더 이상 쓰지 않는 터널과 불필요한 연결 대상을 정리합니다. 다른 본인 작업에서도 사용 중인 터널은 먼저 확인합니다. 터널 삭제에는 Manage 권한이 필요합니다.

기존 키를 교체했다면 더 이상 사용하지 않는 옛 키도 Platform에서 폐기합니다. 앱의 **교체할 전용 키** 입력란에 새 키를 넣는 것만으로 옛 키의 원격 권한이 사라지지는 않습니다.

## 11 마지막 확인 목록

아래 항목을 직접 확인한 뒤 일상 사용을 시작합니다. 아직 확인하지 않은 항목은 완료로 표시하지 않습니다.

- [ ] 해당 Mac 후보의 실행 요건·서명·공증 상태를 확인했다. 음성 엔진의 지원 범위와 앱 실행 요건을 구분했다.
- [ ] 내 개인 Platform 조직과 사용할 ChatGPT 워크스페이스가 대상 터널에 연결되어 있다.
- [ ] 공식 tunnel-client와 앱이 찾을 수 있는 Node.js의 버전·기능 검사가 통과한다.
- [ ] 전용 키는 Restricted Tunnels Read + Use이며, 키 생성 주체의 터널 권한도 확인했다. 키를 채팅이나 공유 문서에 넣지 않았다.
- [ ] 앱에서 정확한 터널·조직을 확인해 Keychain 저장과 연결을 각각 허용했다.
- [ ] 같은 터널의 클라이언트를 중복 실행하지 않으며 앱의 `터널 준비됨` 표시를 확인했다.
- [ ] 개인 플러그인을 Tunnel 방식으로 만들고 설치했으며 `present`와 `cancel`을 발견했다.
- [ ] `speak:false` 요청의 문장이 Mac의 선택한 캐릭터에 실제로 표시된다.
- [ ] 음성 사용 시 기존 패키지·음량·시드·재생 방식을 확인하고 Mac에서 음소거를 직접 해제해 실제 발화를 들었다.
- [ ] 발화 중 취소와 표시 만료를 확인했다. 로컬 대화가 화면을 사용 중일 때의 거절도 이해했다.
- [ ] 자동 연결은 실제 시험 후 원할 때만 별도 허용했다. 다시 연결하면 음소거 상태부터 확인한다.
- [ ] 문맥 지시는 모든 메시지의 자동 출력 보증이 아니며 휴대전화 양방향 음성 기능과 구분된다는 점을 이해했다.
- [ ] 연결 해제·자동 연결 끄기, 로컬 키 삭제, Platform 키 폐기와 터널·플러그인 정리 방법을 알고 있다.
